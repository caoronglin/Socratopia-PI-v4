# Review & Assessment Workflow

权威合同见 `SYSTEM/SPEC/ASSESSMENT_CONTRACT.md`。

## 学习目标

每个目标至少记录：`id / behavior / level / source_anchor / expected_evidence`。

## 形成性验证

优先验证：解释、因果链、辨析、应用、迁移。用户自述“懂了”只作为信号，不直接更新掌握。

## 复习闭环

- `passed`：独立正确；
- `hint_correct`：提示后正确；
- `failed`：仍错误或无法解释。

`failed` 与真实混淆生成 `needs_review` 候选。卡片只针对有遗忘价值/混淆证据的内容，不为所有知识点机械制卡。

## 出题质量

每题必须能追溯到学习目标和教材/来源锚点；有答案与解析。选择题应有互异、非空、合理选项且唯一正确。题型与难度的选择规格见 `references/quiz-generation.md`。

## 错因分类

失败证据必须归因，否则补讲无法定向。分类只描述**错误机制**，不描述掌握度：

| 错因 | 特征 | 补讲方向 |
|---|---|---|
| 概念缺口 | 无法给出定义/边界 | 重建表征，从具体例子入手 |
| 机制断链 | 能复述但说不出因果 | 补推导链，做因果型题 |
| 误读题意 | 会做但读错条件 | 练条件标注与题干复述 |
| 流程失误 | 会做但漏步/算错 | 慢速分步 + 平行题 |
| 过度推广 | 正例对，反例错 | 专练辨析/反例 |
| 检索失败 | 曾经会，现在想不起 | 进入复习闭环，不重讲 |

同一道错题可能多因并存；记录主因并注明次因。错因不是掌握度，禁止据此写 mastery 字段（见 `SYSTEM/schemas/ontology.schema.json`）。

## Rubric 维度

多维评分用于**定位差距**，不是打分排名。可用维度：准确性 / 因果完整性 / 边界意识 / 迁移适用性。差距分析的输出应是"哪个维度缺证据"，而不是"总几分"。分数不写回 coverage 状态。

## 模拟考试

考试只是一次证据采样，不允许一次考试分数直接覆盖长期掌握状态。报告同时给：目标覆盖、表现证据、错误模型、后续验证计划。

## 模拟竞赛

可使用导师团队形式增强参与感，但学习者先独立尝试。导师不得替学习者完成核心作答；结果仍按 assessment evidence 记录。
